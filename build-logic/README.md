# KeiOS build logic

This is an independent Gradle included build. Main `settings.gradle.kts` includes it with
`includeBuild("build-logic")`, outside `pluginManagement`, following
[Gradle's build structure guidance](https://docs.gradle.org/current/userguide/best_practices_structuring_builds.html#favor_composite_builds)
and [MIUIX's migration](https://github.com/compose-miuix-ui/miuix/commit/0657575a0259f89b3863166ec2cef4223ea01156).

Both builds read `gradle/libs.versions.toml`; update AGP/Kotlin versions there rather than adding
independent plugin pins here. This build only resolves build tools from public repositories. App
dependencies and GitHub Packages credentials remain in the main build's settings.

| Convention | Responsibility |
| --- | --- |
| `keios.android.application` | Android application plugin, catalog SDK/JDK defaults, unit test JVM exports |
| `keios.android.library` | Android library defaults and release/diagnostic variant pairing |
| `keios.android.test` | Android test defaults and base diagnostic type for the profile producer |
| `keios.android.compose` | Compose compiler, Java-aligned Kotlin target, SDK minor pin, optional compiler reports |
| `keios.miuix` | Shared MIUIX override precedence and Android artifact substitution |

Apply conventions explicitly in each module's `plugins` block. Keep namespaces, dependency exposure
(`api`/`implementation`), consumer keep rules, app signing/build types, and module-specific test options
in the owning module. Do not configure modules from root `subprojects` or `allprojects` blocks.

`KeiosVersionMetadata.kt` owns the existing Git/CI/local override version calculation and timestamp
provider. The app still owns its release target. `VerifyProfileCaptureTask.kt` guards profile capture
against empty, stale, failed or incomplete device results; the producer module owns its six journeys
and task wiring. Library pairing includes the diagnostic variants generated by the Baseline Profile
plugin. Producer pairing must use the unprefixed base `releaseDiagnostic` to avoid doubled names.

From the repository root:

```bash
# Validate convention plugins and their version/profile guard tests without an Android device.
./gradlew -p build-logic check

# Confirm build-logic is compiled and main-build configuration caching works.
./gradlew help --configuration-cache-problems=fail
./gradlew help --configuration-cache-problems=fail
```

The second `help` should reuse the configuration cache. No device collection or installation is part
of these commands. The main wrapper and Java 21 toolchain remain the project baseline. Compiler
reports can be enabled with `-PcomposeCompilerReports=true` for both Compose modules.
